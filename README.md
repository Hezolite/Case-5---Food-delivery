# Кейс №5. Прогнозирование фактического времени доставки еды

**Проектный практикум-1 · регрессия · команда 5**

## Куда смотреть

**Основной результат проекта — единый ноутбук:**

> **[`Notebooks/Final/unified_food_delivery.ipynb`](Notebooks/Final/unified_food_delivery.ipynb)**

Содержит постановку задачи, EDA, baseline, валидацию, подбор гиперпараметров и финальную оценку. Выполняется сверху вниз без вмешательств, все `random_state` зафиксированы (`RANDOM_STATE = 42`). Для проверки воспроизводимости:

```
jupyter nbconvert --to notebook --execute --inplace Notebooks/Final/unified_food_delivery.ipynb
```

**Данные:** `Data/food_delivery_orders_dataset.csv` — 50 000 заказов, 37 столбцов (Kaggle: Food Delivery Orders & ETA Logistics Dataset).

**Итог модели:** MAE ≈ 2.06 мин на holdout против ≈ 5.2 мин у текущего прогноза платформы (модель HistGradientBoosting + Optuna, признаки только те, что известны в момент заказа).

## Как устроен единый ноутбук

| Раздел | Содержание |
|---|---|
| Шапка | Постановка задачи, формализация, вклад участников |
| 1 | Загрузка данных, техпаспорт, пропуски, дубликаты, санити-чек |
| 2 | EDA: таргет, погода/пробки, опоздания, дистанция, курьеры, PHIK |
| 3–4 | Стратегия предобработки, выбор метрик (MAE — основная) |
| 5 | Схема валидации (5-fold KFold) и baseline: Dummy, Linear, ETA платформы |
| 6 ★ | Сравнение способов масштабирования (метрики + коэффициенты) |
| 7 | Feature engineering: проверка гипотез-взаимодействий |
| 8–9 ★ | GridSearchCV / RandomizedSearchCV + байесовская оптимизация (Optuna) |
| 10 | Финальная оценка на holdout, диагностика остатков, важность признаков |
| 11 | Итоги, ограничения |

Папки `Notebooks/<участник>/` — рабочие ноутбуки этапов (EDA и baseline), из которых собран единый;
